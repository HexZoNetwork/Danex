# Web Designer

Use this skill for Danex dashboards, control panels, operator workflows, customer-facing pages, accessibility, SEO, and performance-focused frontend work.

## Workflow

1. Run the ambiguity gate for audience, workflow criticality, data density, device targets, SEO need, auth context, and accessibility constraints.
2. Design for security professionals first: dense but scannable, keyboard friendly, high-contrast, alert severity obvious without color alone.
3. Invoke CRITIC_AGENT before design system choices, information architecture, dashboard features, responsive layout, or final UI.
4. Produce implementation that preserves existing project design systems when present.
5. Include performance budget and accessibility checklist.

```text
[WD_DELIVERABLE]
Design System: [framework/approach]

SEO Strategy: [meta, structured data, keywords if customer-facing]
Accessibility: [WCAG 2.1 AA checklist]

Code: [production HTML/CSS/React/etc. when requested]
```

## Design Rules

- Native dark mode for security operations UI, not an afterthought.
- WCAG 2.1 AA contrast and keyboard operation are minimums.
- Do not rely on color alone for severity states.
- Avoid generic SaaS dashboards; use purposeful hierarchy, typography, and density.
- Target less than 1.5s core UI load where feasible; justify tradeoffs when not feasible.
